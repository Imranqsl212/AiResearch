# SWE-bench external trace audit

Frozen locally before retrieving the submission catalogue, choosing runs, reading trajectories or consulting their results. This is a prospective selection and coding plan for an exploratory artifact audit. The local timestamp and SHA-256 receipt are not an external preregistration.

## Selection

1. Use the official SWE-bench experiments catalogue, Verified split only, submission directory dates through 2025-12-31. Pin the catalogue commit returned at retrieval. Two prespecified harness families, one published submission each. For family A match SWE-agent (case-insensitive, ignore punctuation and spacing, exclude mini-SWE-agent). For family B match OpenHands or OpenDevin on the same basis, excluding names already matched to A. Use directory names for matching, and sort candidate directories by their full names in ascending ASCII order. If either pool has no eligible submission, use mini-SWE-agent for that family, then remaining named agent submissions in directory order, without reusing a submission.
2. Take the first candidate in each pool with publicly retrievable per-instance prediction IDs, published evaluation outcomes, and an identifiable public collection of agent trajectories. Establish availability from indices, file names or submission documentation, without examining any instance outcome or trajectory content. Record skipped candidates and reason. Try the official catalogue, its linked artifacts or prior official catalogue history for the same submission; never skip because of an observed behavioral finding. Log technical limits. No samples conditioned on resolution, nonempty patches, stop reason or trace length.
3. To compare the same issues across harnesses, intersect the published prediction-ID rosters (including records with an empty patch). Rank distinct IDs by ascending hex SHA-256 of the UTF-8 string `swe-external-audit-20261122-v1|<instance_id>`, breaking ties by ID. Use the first ten in both series. If the intersection has fewer than ten, take it then fill each series in hash order from its remaining roster. Freeze series names, full rosters and the 20 reserved slots before reading their evaluation labels, patch contents or trajectories. Report the conditional sampling frame. No replacing missing slots.

## What is audited

The unit is a submission × issue. For each unit keep sources, content hashes, trace locations, extraction code, and a row even if evidence is missing. Compare two explicitly different views. View 1 uses only published outcome and submitted patch presence. Record whether the benchmark classified an issue as resolved and whether a nonempty patch is present. For model-issued editing, explicit terminal action and termination cause this view normally yields unknown. Do not impute that failure means giving up, success means voluntary completion, or a nonempty patch proves who edited it.

View 2 adds the public trace, harness events and per-instance evaluation record where available. Code these separately:

- Actions: at least one observable edit attempt, a confirmed modification if supported by a tool result or diff, verification/test attempt, explicit agent request to finish, and last observable agent action. An intention in prose is insufficient for an executed tool action. A command request does not certify a successful edit or passing test.
- Stop: distinguish an agent-issued submit/finish action, a controller/system budget/timeout/error boundary, their coexistence, and unknown. A recorded final action alone does not establish which actor ended the run. An explicit submit followed by the matching harness acknowledgment/exit status can support an agent-requested termination. Otherwise report the narrower observation. No inferences about private reasoning or motivation.
- Outcome: compare published resolution with instance-level evaluator output when available. Keep unassessable outcomes separate. Diff equality only when the same byte representation or an explicitly documented normalization is available. Absence of an event in a partial or unvalidated trace is unknown.

For each coded claim, classify its change as newly supported, contradicted (requires an actual explicit claim in view 1 and affirmative contrary evidence), unchanged or unresolved. Separately flag counterexamples to two *hypothetical* shortcuts: an unresolved run ended without an explicit finish; a resolved run necessarily ended by the agent's choice. These are not claims made by the leaderboard. State denominators and missing evidence for every headline. Report per-series counts, matched issue examples, negative and null results. No significance tests, general capability ranking or estimation of prevalence beyond the selected runs.

## Verification and constraints

Use read-only public artifact access and ordinary local text processing. Do not run a model, submitted patch or test command from a trajectory. Retain only the public action or event evidence needed for reporting; avoid reproducing free-form reasoning. Seek a separate coding check on terminal cases, disclose whether it is automated, and report material disagreements. A second human adjudication is not assumed. If artifacts cannot answer a question, report that limit.
