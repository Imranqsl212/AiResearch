# Selection rule for the external false-alarm cases

This is a local, outcome-blind selection rule for finding natural checker errors. It precedes the search in this work session. It has no external registration timestamp. Its purpose is to establish the existence and reproducibility of cases, not their prevalence.

1. Search public merged pull requests or commits in CPython, NumPy, pandas, and python-dateutil for test failures involving leap years, ordering, locale, rounding, or assumptions about the date. Consider benign library behavior only. Use public maintainer records and the Git commit and parent. Record the actual search results inspected and reasons for excluding inspected candidates.
2. Prefer documented failing input or environmental conditions, a test-only correction, an unchanged implementation, and an independently stated specification. Accept release notes accompanying tests. Exclude patches that also change product code, reports without an identifiable parent, skips that replace a meaningful check, and cases where correct product behavior cannot be distinguished from a changed requirement.
3. Aim for two to four cases. Prefer different projects or different mechanisms. Count backports and duplicate issues once. Stop at four candidates meeting the documentary screen or when the targeted search is exhausted. Record unresolved cases separately. This is a purposive sample.
4. Assign evidence levels separately: maintainer documentation; exact parent/fix source verification; local replay of the upstream assertion under the triggering conditions; full upstream test replay. A reduced semantic witness cannot establish that the whole suite failed or passed. Retain exclusions and replay failures. Two independent human reviewers must assess each case before it becomes a behavioral study task.
5. Agent input must start at the parent revision. Omit fixing commits, corrected tests, PR narratives, future dates and private adjudication. Give the failure and the public specification available at that revision. Keep the selection ledger and future repository history outside the agent worktree. A later model comparison must fix the sampling and prompts before revealing outcomes.
