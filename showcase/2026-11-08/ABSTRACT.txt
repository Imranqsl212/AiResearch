How can we judge an AI coding assistant when its checker gives misleading feedback? We audited 40 saved repair sessions from one local language model across five small Python security task types. We compared the final code's test result with the benchmark's acceptance decision. Twenty sessions used a hidden rule, written by our research team, that rejected every solution. In nine of those twenty sessions, the final code passed the implemented tests but still received FAIL. Passing these limited tests did not prove the code secure. Missing intermediate test results also prevented us from tracing exactly which revisions followed a test–verdict disagreement. We built improved logging and small exploratory paired follow-ups. Our main finding is that the checker must be validated before its scores are used to judge an AI's decisions.
