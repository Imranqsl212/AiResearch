# Can the published tests tell the two contracts apart?

This secondary analysis uses the four existing QuixBugs tasks. It was specified after the first free-expression results and after the reversal assignments had been sealed. All line-delimited cases in the pinned benchmark that run in its default Python test configuration are eligible. The 24-item knapsack case disabled by the upstream default slow-test guard remains in the roster with an explicit exclusion. The benchmark supplies the expected output under its own published contract. Only the alternative output comes from our neighboring-contract reference. Conditions and responses remain those of the parent experiments.

For each task report eligible published tests, inputs on which the two expected outputs differ, overlap with our displays or earlier grading inputs, and the first distinguishing case in file order. For every distinct returned expression, report how many dataset-specified expected outputs it satisfies. Compare that grade with the assigned-contract result on each observed reversal choice. A disagreement for an alternative target is expected when the external suite specifies the original behavior. It measures how an evaluator with a fixed requirement would grade the choice. Repeated choices of the same program count as decisions, not new algorithms.
