# Retrieval corpus review — 4 October 2026

## Scope and method

Reviewed all 20 rows of [`benchmark/retrieval_corpus_v1.jsonl`](../benchmark/retrieval_corpus_v1.jsonl) against the public projections, exact references, hidden task facts, proofs and C1–C5 modes in authorization v1, path-boundary v2 and transaction-replay v3. Compared each canonical JSON-row SHA-256 with [`retrieval_manifest_v1.json`](../benchmark/retrieval_manifest_v1.json); all 20 match. The raw corpus SHA-256 is `8fb4dabffc9891179c91bd8419f2c5762686ba5ae307fa9b213d44ef85c2a56d`, and the retrieval manifest SHA-256 is `309101bfa7724094602a6f3983020869b2725f6582226ccfa4ca7beebfda8cdc`.

**Leak result:** no row gives an exact JSON candidate table, exact output mapping, `role=...` observation, `assets/current` mapping, `fresh`/`seen` transition, hidden contradiction state, condition identifier, proof, oracle verdict or C5 gate mode for any of the three controlled fixtures. The security principles in some rows are intentionally useful guidance; that is the RAG treatment, not an answer-key leak. This is a bounded manual review of the current three fixtures, not a guarantee for future tasks or hidden semantic contamination.

The source links below were checked against official NIST, OWASP, MITRE CWE or RFC Editor pages for **topic relevance** on this date. The direct CWE-22 fetch timed out once; the official indexed page was reachable through search. Current web pages can change, and their source versions or full page bytes are not pinned in the corpus. This review does not certify every paraphrased clause as a quote from its linked page. `PARTIAL` marks a specific clause that needs a more direct citation or revised wording before a study freeze.

## Exposure check and release limit

Using the current saved retrieval manifest and exact public C1 projections, authorization R1 returns `web-authorization-v1`, then `web-path-traversal-v1`; path-boundary R1 returns `web-path-traversal-v1`, then `web-authorization-v1`. The first rank is relevant in each case, but the second is cross-family material. Their R2 arms intentionally replace the second result with a crypto-domain document. These are deterministic retrieval outputs, not evidence that an agent used either document. The R0/R1/R2 contexts differ in text and length; source relevance alone cannot identify a RAG content effect.

The current corpus has **12 crypto rows, eight web rows and zero payments rows**. The current `benchmark/retrieval_v1.py` rejects `payments` at public-query construction, so the replay v3 task cannot enter a matched R0/R1/R2 comparison with this implementation. Adding payments material would create a new corpus/version/hash and require a new review. The five `PARTIAL` citation rows above also need adjudication before calling the corpus independently reviewed. This document records an audit; it does **not** declare a main-study RAG freeze or alter the corpus.
