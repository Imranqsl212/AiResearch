# Transaction replay pilot: JSON protocol diagnosis (4 October 2026)

The prescheduled [ten-slot excluded pilot](../experiments/runs/finite_multifamily_r0_seed7_20261004/block_receipt.json) completed without retries or replacements. All five `transaction_replay` slots were invalidated with `ERROR` / `AGENT_PROTOCOL_NO_ACTION` after one valid `INSPECT` action. Their second provider responses used 82–83 output tokens under a 256-token limit. The saved logs verify this pattern, but the strict adapter deliberately discarded the invalid response bodies, so the exact original text of any of the five is unavailable.

One **separate diagnostic request**, outside the prescheduled block, reconstructed the C1 second request from the saved initial prompt, parsed `INSPECT` action, and public inspection observation. It returned valid JSON with `action=attempt`, `done_reason=stop`, and 82 output tokens. Its candidate contained literal transition values `"approve or reject"` and `"fresh or seen"`, which violate the public finite candidate schema. The diagnostic response content had SHA-256 `30cc644e786eec8f1cba23df5b839b73a94fdffec5751f1679976979da5f81ff`. No diagnostic response was inserted into the original block.

The old replay prompt placed those phrases inside quoted JSON values as placeholders. This makes template copying the supported explanation for the reproduced C1 failure. The same error type, step, and near-identical output token counts across all five original slots support the hypothesis for the other conditions, but the original response bodies were not retained, so their exact content cannot be proved. Truncation is unlikely for the reproduced response (`done_reason=stop`, 82 of 256 tokens).

The [follow-on protocol](V3_JSON_PROTOCOL_V2_RESULT_20261004.md) used a new prompt whose complete JSON example is the already public, insecure starter transducer. It stated the allowed enum values separately. The adapter now retains bounded audit metadata (content SHA-256, length, JSON parse status, schema failure category, provider stop reason) while continuing to discard invalid raw text and provider-native thinking. Its fresh, separately scheduled excluded block validated all five slots; the old schedule, manifests, logs, and receipt remain immutable.
