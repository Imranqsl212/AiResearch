**Status: `EXCLUDED_PROTOTYPE_UNREVIEWED`.** This is a new candidate corpus, not an amendment to the R1 pilot input and not a main-study retrieval freeze. The [v0.1 corpus](../benchmark/retrieval_corpus_r1_20_candidate.jsonl), [manifest](../benchmark/retrieval_manifest_r1_20_candidate.json), and [provider](../benchmark/retrieval_r1_20_candidate.py) remain byte-for-byte the earlier excluded pilot inputs. The 40-slot R1 live feasibility results in [its audit](R1_TWENTY_LIVE_FEASIBILITY_20261005.md) concern v0.1 only; no model has been run with v0.2.

The [v0.2 corpus](../benchmark/retrieval_corpus_r1_20_candidate_v2.jsonl) has 20 one-document-per-family rows. Seven source paragraphs changed and 13 retain the earlier source and text; all 20 document IDs have a distinct `r1-20-v2-` prefix. The [provider](../benchmark/retrieval_r1_20_candidate_v2.py) pins the v0.1 corpus and implementation hashes and reuses its public-card query, domain filter, lexical scoring, top-one choice, and exploratory R2 noise procedure. The [manifest](../benchmark/retrieval_manifest_r1_20_candidate_v2.json) binds the v0.2 provider, corpus, all document rows, and all 20 public C1–C5 projections.

| `transaction_replay` | Separated a server-side transaction authorization credential from an API request idempotency key. [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html) discusses unique authorization credentials; [Stripe](https://docs.stripe.com/api/idempotent_requests) describes using a key to recognize a request retry. | `ambiguous_parameters` | Describes parser disagreement as a conditional risk. These are different mechanisms; UTS #39 says a skeleton is not identifier normalization. Neither specifies the application's principal-equality policy. |
| `csrf_origin` | Mentions both token validation and origin checking as defenses with deployment assumptions. [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) presents fallback and layered cases, so the source does not mandate their conjunction for every application. |
| `key_rotation` | States that treatment of a retired key depends on artifact and application policy. [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Key_Management_Cheat_Sheet.html) permits retaining public verification keys for archived signatures; it does not establish a universal current-key-only rule. |

MITRE distinguishes CWE-426 from a writable element in an otherwise fixed path (CWE-427). Neither defines the finite task's exact safe environment keys. |
