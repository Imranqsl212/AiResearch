# Opposing target conventions on unchanged benchmark code

This exploratory study tests whether a model can produce patches in opposite directions for the same publicly familiar source, depending on the supplied target behavior. It uses all four algorithms and both published starts in the previously frozen free-expression panel. We derived the alternative conventions by reading the upstream defective programs. The benchmark maintainers specified the original convention only, and its published labels remain correct under that convention. This construction cannot establish how often a bug implements another meaningful specification.

## Why each neighboring rule fits the source

- In maximum sublist sum, the defective running total begins at zero and accumulates each value without resetting. It is the prefix sum at each position. The outer maximum, initialized to zero, gives the largest prefix sum including the empty prefix. The benchmark requires the largest sum of any contiguous sublist.
- In balanced parentheses, every negative running depth is rejected. A string that survives with final depth d can be completed by appending d right parentheses. Thus returning true after the scan recognizes extendible prefixes. Requiring d to be zero recognizes complete balanced strings.
- In quicksort, the pivot appears once. The faulty partition drops all other values equal to it, recursing on strictly smaller and strictly larger elements. By induction on length, it returns the distinct sorted values. The benchmark requires sorted values with multiplicities.
- In zero–one knapsack with positive weights and values, the faulty guard admits weight w only when w < j. Conditional on taking that item, its remaining positive allowance j − w inherits the strict constraint; a zero-value empty packing remains possible. Induction over the item prefix gives the optimum subject to total weight < j, with empty packing permitted also at zero capacity. The surrounding recurrence always also permits skipping an item. The benchmark permits equality.
