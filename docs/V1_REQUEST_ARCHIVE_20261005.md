# Per-request archive for future v1 finite-policy episodes

The local v1 Ollama adapter now calls a write-once recorder **before each provider dispatch**. For episode `E`, it saves `E.request-000001.json`, `E.request-000002.json`, and so on beside the episode log. Each file contains the exact loopback endpoint and complete JSON request envelope handed to the provider client, including model, public conversation, action schema, and decoding options. If writing fails, the provider request is not sent and the episode is invalidated. Provider-native private thinking is never saved.

The episode manifest indexes every request file with its sequence and SHA-256 and marks whether the archive is complete. `analysis.v1_pipeline.load_episode` verifies bytes, contiguous sequence, count against the terminal request count, the first request against the separately saved prompt and episode seed/temperature, every later request's unchanged options and schema, and its exact assistant-action/public-observation continuation. It rejects extra request files, including symlink aliases. The main release gate requires this archive for every main episode. Older excluded pilots remain readable without the marker, but cannot be promoted to main.

For a prospective main release, the analysis gate additionally requires the complete enumerated implementation inventory in clean source snapshots taken before provider dispatch and after the run. Both snapshots must match the frozen schedule and each other; reconstruction also requires the analysis checkout's implementation bytes to match that freeze. The episode budgets, protocol, and decoding options must match the root schedule's `inference_config`, with B3 for R0 and B5 for retrieval arms in the current plan. The gate rebuilds the first system message from the prompt template in the frozen Git commit and the first user messages from the finite task's public projection, deterministic retrieval documents, and independently evaluated starter observation. It compares that rebuilt request with both saved prompt and archived first request, so rehashing a jointly altered prompt and request does not suffice. These are release checks, not a claim that the currently blocked main collector is ready.

The archive establishes **exposure**, not document use or comprehension. A retrieved document in a request does not show that the model relied on it. Request bytes and local hashes also do not authenticate the provider's unseen internal execution or provide an independently held timestamp. The initial prompt is bound to the saved public start observation, but the current excluded collector is not a complete main-study source-release implementation. New main data still require a frozen source/corpus, independently held archive, and all other scientific gates.

Focused regression checks are in `tests/test_v1_collector.py`, `tests/test_v1_ollama_adapter.py`, and `tests/test_v1_analysis.py`: they compare archived requests with arguments observed by a mock provider, reject tampering, prove archive failure prevents dispatch, and reject self-consistent changes to the first public prompt.
