# Repeating the target and caption experiments in a second collection window

This exploratory replication uses fresh hosted editing sessions on the same starting programs. All four QuixBugs algorithms and the first complete eight-block caption panel enter by their original assignments. The two windows are successive subscription periods on the same account. Elapsed time, the hosted service and sampling can all contribute to differences between them.

| Panel | Fixed model–task–start blocks | New decisions per block | Planned calls |
| --- | ---: | ---: | ---: |
| QuixBugs | 16 | 2 target answers × 2 levels of rule description | 64 |
| Execution captions | 8 | 1 blind choice + 2 outputs × 4 captions | 72 |

**Primary comparison.** In each QuixBugs block, score whether two separate responses implement the upstream and alternative contracts when each is requested and both rules are described. Compare the same block across windows. Report the two success counts, blocks that succeed only in the first window and blocks that succeed only in the second. Identical marginal counts can conceal different successful blocks.

**Caption comparison.** Within the second window, compare the original unspecified-candidate caption with the same caption followed by the original disclosure that the output was selected independently of the installation's required behavior. Count blocks in which the model selects the producing program for both opposing values. The same fresh unspecified-caption decisions supply the control for this contrast and the comparison with the first window. The first window collected zero disclosed-caption decisions.

**Other outcomes.** Report the other captions, the blind choice, upstream and alternative success, and repair of defective starts separately from preservation of working starts under an assigned requirement. Compare both rule-description conditions within each window. For omitted descriptions, distinguish the nine blocks completed in the original window from the seven that lacked original responses. Keep raw numerators and denominators by window. A response to an unspecified candidate's execution has no uniquely assigned correct behavior.

Use the original prompt bytes, requested model aliases, reasoning effort, finite graders and available editing actions. Keep one native attempt per assigned call in the frozen order. Grade pair outcomes only where the needed responses were observed and give bounds over scheduled comparisons when outcomes are missing. All technical failures and unsent assignments retain their places. Stop at the roster boundary or if the authorized subscription window closes. Preserve the first window's plans, ledgers and all uncollected assignments.
