# Does a new execution help after the first CPython edit?

Exploratory extension of the CPython post-edit pilot. The previous outcomes and the lexical sorting error were already known when this design was written. The admission set is all sixteen archived CPython first choices, including the four histories in which Luna selected the same faulty lexical sort and the twelve histories with passing code. Each history supplies one matched block, not a separate task. Independent human case review is pending.

Each block has three contemporaneously collected continuations. The originating model receives the archived first exchange, current source, original replacement IDs and one further decision at low effort. In the **none** condition the new execution paragraph is omitted. In **shared**, the current implementation is run on integer keys 3 and 7. In **revealing**, it is run on keys 3 and 20. The larger key is always inserted first with the value cobalt, followed by the smaller key with amber. Both inputs are new to the archived exchange. For the observed lexical-sort defect and both eligible correct implementations, the first probe produces the same output, while the second distinguishes their order. Both displays state the actual input and output. Neither provides a reference answer or verdict. Earlier feedback, the specification and the code remain available in all three arms.

The fixed schedule uses seed 20261128 to shuffle histories, counterbalance arm position within each model and starting-correctness group, and shuffle dispatch blocks. Run the three calls in each block consecutively and serially via the ChatGPT-authenticated Codex CLI, without model tools or API keys. The two model aliases are those requested in the parent study. Freeze the study design, executable sources, calibration and all 48 prompt hashes before dispatch. One attempted completion per assignment. Keep interrupted, invalid and missing responses in the public ledger. Halt dispatch on account or network failure; no model substitution or resampling.

Primary descriptive comparison: within the four faulty starts, compare recovery after a revealing display with recovery when no new output was displayed. Report all three arms, repair among faulty starts and preservation among working starts separately, together with counts passing in both, only one, or neither member of each complete paired comparison. Declare all assigned denominators and any missingness. Also report source changes among passing starts as a secondary measure. Grade on exactly the ten prior held-out binding and ordering checks. No aggregate over unrelated tasks, equivalence test or claim about internal reasoning is planned. A difference from the none arm concerns the incremental effect of presenting that execution and its framing, conditional on the archived history. The four faulty starts repeat a single model and defect. The previous day's two-arm outcomes are historical context.
