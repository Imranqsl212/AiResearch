At the initial review these were prerequisites, not permission to bypass a
gate. That candidate had an immutable local repository digest but had not yet
been approved. The initial no-agent-run decision was later superseded by
separate excluded pilot receipts; it never authorized prospective main.

1. **Initial runtime namespace and daemon gate were unverified.** The old candidate result documents Docker rejecting `--pid private` before creation. The revised policy no longer passed unsupported `--pid private`/`--userns private`; it required Docker's private PID default, daemon-level user-namespace remapping on native Linux **or the explicitly verified Docker Desktop `desktop-linux` LinuxKit VM boundary**, seccomp, and effective-mode checks before start. The Codex permission profile at that point could not access the Docker socket. **Historical action:** run the candidate suite with local Docker Desktop access, verify the context/OSType/LinuxKit identity and effective container configuration, and obtain an independent review of the VM-boundary assumption. Do not set `--userns=host`, disable the daemon prerequisite, or treat static tests as runtime proof.
2. **Later image approval and runtime containment — CLEARED for that local Docker Desktop boundary.** The exact digest-pinned candidate passed all nine candidate probes and the official suite available at that time. Its receipt recorded `overall_passed=true`, `experiment_permitted=true`, and `isolation_mode=docker-desktop-linuxkit-vm`. The mutable `latest_result.json` has since been replaced by a later 11-check receipt; it is not the nine-check record described here. This cleared only that sandbox image gate. Any image, policy, code, or daemon change required a new candidate and official run; the VM/daemon escape assumption remained documented.
3. **Container target/verifier integration is incomplete.** The candidate binary offers a bounded local engineering interaction, but its final state is not exposed through an independent evaluator-only verifier channel and it is not the nine-task benchmark. The in-memory pilot now emits action-time receipts, but they share its authored graph and do not establish executable ground truth. **Action:** design and test evaluator-only action and terminal receipts for one executable local task, prove that the agent sees neither condition nor oracle, test verifier false-positive/false-negative cases, calibrate verifier overhead under the episode deadline, and tie the exact executable image to a versioned task manifest. Do not count a target observation or agent claim as success.
4. **Pilot difficulty and distractor validity are unresolved.** A separate 12-manifest v0.2.0 development suite now has matched `RD/UD/RW/UW` cells, identical public projections and transition counts, and a separate receipt contract. Static parity is not an executable infrastructure proof: distractor/weak-feedback plausibility, independent reachability, and runtime verifier behavior still need review. **Action:** have independent reviewers validate the four-cell suite, test byte-identical pre-index behavior, prove alternate paths and unreachability on the executable target, document the preregistration amendment, and only then run a development pilot. Do not map the old three-condition pilot onto the four cells.
5. **No legitimate provider-backed adapter is selected or implemented.** Only the abstract lifecycle and scripted fixture exist. **Action:** choose a permitted API or agent runtime under its actual terms and practical budget; configure authentication on the host only; freeze model/harness/prompts and log public actions and token usage without chain-of-thought. Test that condition, ground truth, verifier state, hidden task state, host files, and credentials never enter the provider request or sandbox. Do not automate a consumer subscription or bypass limits.
6. **No frozen experiment revision or real smoke evidence exists.** The source baseline `33b3d7acfc7cea0b83f96bae9f2f26d0127152da` is not a study freeze. The only stored trajectory predates Git and remains an excluded fixture. **Action:** after blockers 1–5, commit and freeze task definitions, image digest, verifier, adapter, preregistration, and configuration; require a clean or explicitly archived worktree; run exactly one `SMOKE_TEST` with complete logs, independent receipt, isolation and cleanup checks. Keep it outside the scientific dataset. Only after that may pilot readiness be reassessed.

The official safety gate remains fail-closed. A nonzero check or `NOT_RUN` is not an invitation to adjust the result; it is a reason to stop execution and investigate.
