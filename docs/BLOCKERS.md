# Blocking conditions and exact next actions

These are prerequisites, not permission to bypass a gate. The current candidate has an immutable local repository digest but is **not approved**. No agent experiment may run.

1. **Docker namespace policy cannot create a container on this daemon.** The existing `--pid private` argument is rejected by Docker. [Docker's run reference](https://docs.docker.com/reference/cli/docker/container/run) defines private PID isolation as the default, not a valid explicit mode, and states that `host` is the only explicit `--userns` value. The daemon currently reports `seccomp` and `cgroupns`, but no user-namespace remapping. **Action:** on a dedicated local Docker configuration, arrange reviewed daemon-level user namespace isolation or an equivalently documented Docker Desktop Enhanced Container Isolation mode. Then redesign the policy to use only Docker-supported options *while still requiring and measuring* private PID/user isolation; update static and runtime tests; obtain security review. Do not simply remove the invalid flags or set `--userns=host`. Host-wide Docker configuration was not changed here because it can affect other workloads.
2. **Image approval and runtime containment remain unproven.** The fixed candidate lock is separate from the empty official `approved_images.json`. [Preapproval result](../sandbox/safety_checks/candidate_result.json) has one runtime `FAIL` and eight `NOT_RUN_FAIL_CLOSED`. **Action:** after blocker 1, rebuild/inspect the exact content-addressed candidate, verify source/binary/image hashes and no secret-bearing layers, run the full candidate suite until *every* runtime check passes, then record the reviewed digest in the official lock and rerun the official suite. Any changed digest needs a new review. No mutable tag, image ID, or unverified registry reference substitutes for the repository digest.
3. **Container target/verifier integration is incomplete.** The candidate binary offers a bounded local engineering interaction, but its final state is not exposed through an independent evaluator-only verifier channel and it is not the nine-task benchmark. **Action:** design and test an evaluator-only receipt for one local task, prove that the agent sees neither condition nor oracle, test verifier false-positive/false-negative cases, and tie the exact executable image to a versioned task manifest. Do not count a target observation or agent claim as success.
4. **Pilot difficulty and distractor validity are unresolved.** Static graph reachability passes, but each `SOLVABLE`/`DISTRACTOR`/`UNSOLVABLE` task has 3/5/4 transitions respectively; distractor plausibility has not been independently judged, and a graph proof is not an executable infrastructure proof. **Action:** have independent reviewers validate a matched nine-task redesign, check identical pre-failure interfaces/budgets, genuine distractor plausibility, reference paths and unreachability, then version tasks and document any preregistration amendment *before* real-agent data. Do not silently map the three pilot labels onto the four proposed confirmatory cells.
5. **No legitimate provider-backed adapter is selected or implemented.** Only the abstract lifecycle and scripted fixture exist. **Action:** choose a permitted API or agent runtime under its actual terms and practical budget; configure authentication on the host only; freeze model/harness/prompts and log public actions and token usage without chain-of-thought. Test that condition, ground truth, verifier state, hidden task state, host files, and credentials never enter the provider request or sandbox. Do not automate a consumer subscription or bypass limits.
6. **No frozen experiment revision or real smoke evidence exists.** The source baseline `33b3d7acfc7cea0b83f96bae9f2f26d0127152da` is not a study freeze. The only stored trajectory predates Git and remains an excluded fixture. **Action:** after blockers 1–5, commit and freeze task definitions, image digest, verifier, adapter, preregistration, and configuration; require a clean or explicitly archived worktree; run exactly one `SMOKE_TEST` with complete logs, independent receipt, isolation and cleanup checks. Keep it outside the scientific dataset. Only after that may pilot readiness be reassessed.

The official safety gate remains fail-closed. A nonzero check or `NOT_RUN` is not an invitation to adjust the result; it is a reason to stop execution and investigate.
