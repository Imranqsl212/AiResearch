# What can repeating a test command establish in a public SWE-bench trace?

This exploratory secondary audit reuses all twenty slots in the existing hash-selected SWE-bench Verified sample, ten matched issues in each of two submissions. Their earlier stopping and editing summaries were known before this protocol was written. Freeze this specification locally before extracting repeat-command outcomes. Keep missing traces and unrecognized outcomes explicit. The unit is an episode, and the same issue can appear in both submissions.

For each available trace, read only structured tool invocations and their linked observations. Never execute a recorded command. Admit an isolated, single-line invocation of pytest, Django's runtests.py, Python running a .py file, or Python -m pytest/unittest. Exclude shell pipelines, redirection, compound commands and inline code. Hash the exact whitespace-trimmed command text. Detect reuse of the identical text at two or more positions within an episode. This measures a repeated command string. A test script, working directory, code under test or environment may change between the calls.

For the first and last recorded executions of each repeated command, extract a test verdict only from the tool response. Recognize pytest numerical pass/fail summaries, and unittest/Django terminal OK/FAILED following a 'Ran N tests' summary with N greater than zero. A zero process exit code, an exception alone, or an agent's claim of success supplies no test verdict under this rule. Identify whether any one repeated command changes from a recorded failing test suite to a recorded passing suite. Separately record, solely for the OpenHands series with explicit process exits, any repeated command changing from nonzero to zero (first to last). Count episode-level repeats, available formal verdict pairs and observed fail-to-pass witnesses. Inspect every positive locator and document its interpretation. Join the pinned benchmark evaluator resolved status only after coding. Report it separately from all intermediate test and process outcomes.

This coding rule is deliberately narrow. Counts are lower bounds on observable forms of rerunning within these records. Absence of a repeated string cannot establish absence of testing. Even matching commands and a fail-to-pass transition cannot identify a change in the agent's decision attributable to feedback. Do not use the two historical submissions as a ranking.
